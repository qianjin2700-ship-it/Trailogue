# 07 — 照片元数据三级降级流程

## 0. 目标

微信生态的照片经常丢失 EXIF（聊天转发、截图、压缩），系统必须在不依赖完整 EXIF 的前提下，尽量还原每张照片的**时间**与**地点**，并明确标注每个值的**来源与置信度**，最终交给用户确认。

## 1. 总体决策树

```
照片上传完成（commitUpload）
│
├─【第一级 EXIF】云端 exifr 解析原图
│   ├─ DateTimeOriginal 有效 → taken_at = EXIF值，source=exif，confidence=1.0
│   ├─ 无 DateTimeOriginal 但有 CreateDate/ModifyDate → source=exif，confidence=0.9
│   ├─ GPSLatitude/GPSLongitude 有效（含方向位校验，中国境内范围校验 3~54N/73~135E 可配置）
│   │     → geo_cache 查询（4 位小数键）
│   │        ├─ 命中 → location 直接回填
│   │        └─ 未命中 → 腾讯位置服务逆解析 → 写缓存 → 回填 source=exif, confidence=1.0
│   └─ Orientation 读取（1~8），用于前端显示校正
│
├─【第二级 自动推断】仅当第一级对应字段缺失时触发
│   ├─ 时间推断：
│   │   ├─ 文件修改时间（云存储对象 meta）有效且与相邻照片时序不矛盾
│   │   │     → source=file_meta, confidence=0.5
│   │   ├─ 前端 client_hint（本地文件时间，上传时携带）→ source=file_meta, confidence=0.5
│   │   └─ 仍然缺失 → 等待视觉理解后做邻接推断：
│   │         若前后相邻照片时间已知且同组 → 插值估计
│   │         → source=inferred, confidence=0.3（不参与排序主导，仅展示参考）
│   ├─ 地点推断：
│   │   ├─ 同一时间组内其他照片有 EXIF 地点 → 沿用该地点
│   │   │     → source=inferred, confidence=0.4
│   └─ 视觉模型识别出明确地标（landmark 置信度 ≥0.8）
│   │         → source=inferred, confidence=0.6（仍标黄，需用户确认）
│   ├─ 视觉模型识别内容（多模态推断）：
│   │   ├─ 地标/建筑识别（landmark）
│   │   ├─ 风景类型（海滩/山地/城市/室内）
│   │   ├─ 天气/季节/昼夜
│   │   ├─ 食物识别
│   │   ├─ 人物活动/活动场景
│   │   └─ 图片之间可能的连续关系（邻接推断）
│   └─ 推断规则：
│       ├─ 所有推断结果标注：推断依据、数据来源、置信度、关联照片 ID
│       ├─ 低置信度信息不得作为确定事实直接写入故事
│       ├─ 不得仅凭视觉相似性断定具体地点、人物身份或人物关系
│       └─ 可利用同组高置信度照片辅助推断，但不得将推断伪装成确定事实
│
├─【第三级 用户补充】photo-review 页交互
│   ├─ 高置信项（绿）：直接展示，可修改
│   ├─ 低置信项（黄）：默认待确认；采纳→保持推断值但 user_confirmed=true；
│   │     修改→ source=user, confidence=1.0；标为未知→ source=unknown
│   ├─ 未知项（灰）：引导补填；用户填写的城市/日期 → source=user, confidence=1.0
│   └─ 用户可补充：城市、日期或日期范围、活动地点、活动类型、人物关系、希望强调的事件
│      允许选择「未知」或跳过；用户确认或补充的信息优先级高于系统推断
│      用户修改后保留修改来源，不得再次被模型推断覆盖
│
└─ 汇总进入 confirmMeta → 事实库快照（分档标注随快照固化）
```

## 2. 关键规则

### 2.1 优先级与覆盖
`user（第三级）> exif（第一级）> file_meta/inferred（第二级）> unknown`
- 用户修改后系统不得再回写覆盖；
- 重新处理（requestMetaProcess）只作用于 `user_confirmed=false` 的字段。

### 2.2 置信度写入故事的规则（与 06 号文档联动）
| 来源标签 | confidence | 能否进入故事正文 |
|---------|-----------|----------------|
| exif / user | 1.0 | ✅ 可直接陈述（"在塔尔寺"） |
| inferred（地标≥0.8） | 0.6+ | ⚠️ 中性表达（"画面里是庄严的塔尔寺"→ 由模型按推断档措辞） |
| inferred（其他） | <0.6 | ❌ 不写入正文 |
| unknown | — | ❌ 不提及或模糊指代（"某个晴朗的下午"） |

### 2.3 时序一致性校验（第二级防错）
- 推断时间不得晚于上传时间，不得早于 1970；
- 同一相册内，若推断时间与已确认时间的照片产生 >24h 的乱序跳变，标记该推断为可疑（confidence 降为 0.2，UI 标黄）；
- 排序主键：`taken_at` 优先；`taken_at_source=unknown` 的照片排在**用户指定的插入位置**或组末尾（用户可在 review 页拖动）。

### 2.4 地理校验
- 经纬度在中国境外（可配置开关：仅中国境内）或为 (0,0) → 视为无效 GPS，降级处理；
- 同照片 GPS 与相邻照片 GPS 距离 > 500km → 疑似定位漂移（如相机时区/缓存 GPS），标黄待确认。

## 3. 聚类（分组）算法

> 前置依赖：视觉理解（internal-processVision）已完成——图片内容是聚类第三维度，必须在分组前执行完毕。

输入：确认后的照片（时间 + 地点 + 视觉 facts）
```
1. 按 taken_at 升序排序（unknown 时间的照片按用户指定位置插入；
   完全无时间时，以视觉内容连续性作为排序辅助信号）
2. 顺序扫描，满足任一条件则切分新组：
   a. 与前一张时间差 > TH_HOURS（默认 6h，**阈值可配置**）
   b. 与前一张地理距离 > TK_KM（默认 30km，Haversine，**阈值可配置**，任一坐标缺失则跳过该判据）
   c. 内容明显切换：与前一张的场景/地标 facts 相似度低于阈值
      （scene type 变化且无共同 landmark；仅当 a/b 均无法判定时启用）
3. 组数上限 10；超出时增大阈值（×1.5）重跑，直到 ≤10
4. 每组生成 photo_groups：title="第N段 · {城市|主题}"，location_label 聚合
5. 单张成组且前后组时间差 < 12h → 并入前组（避免孤立单图章节）
6. 兜底归组：仍处于组外的照片（无时间且无地点），按视觉内容相似度
   归入相邻组（相似度最高者），并在 review 页标注"按内容归组"
7. 用户可：调整照片顺序、移动照片到其他分组、合并分组、拆分分组、
   修改章节标题、删除不需要的照片
8. 系统不在用户未确认的情况下永久改变原始照片顺序
```

### 内容相似度判定（规则版，MVP 不用模型计算向量）
- 共同 landmark fact（conf≥0.8）→ 高相似；
- scene type 相同（如同为"海滩"）→ 中相似；
- time_of_day 一致 → 弱加权；
- 综合：高相似强归同组；中/弱相似仅在 a/b 判据失效时作为切分/归组参考。

## 4. 状态与展示映射

| photos 字段组合 | UI 徽标 | review 页默认态 |
|----------------|---------|----------------|
| source=exif/user | 🟢 绿「已确认」 | 直接通过 |
| source=inferred, conf≥0.6 | 🟡 黄「推断」 | 待确认卡 |
| source=inferred, conf<0.6 | 🟡 黄「低置信」 | 待确认卡（默认折叠细节） |
| source=file_meta | 🟡 黄「文件时间」 | 待确认卡 |
| source=unknown | ⚪ 灰「未知」 | 引导补填 |

## 5. 异常兜底

| 异常 | 处理 |
|------|------|
| exifr 解析崩溃（文件损坏） | 捕获 → 全字段走二级 |
| 逆地址解析接口失败/限流 | 重试 1 次 → 失败则 location 保留坐标，城市/POI 空，故事中用"坐标附近区域"或忽略；geo_cache 不写脏数据 |
| 视觉理解失败 | 单批重试 1 次 → 仍失败标记 photos.vision.status=failed 并计入 failed_photo_ids，**阻断故事生成**；前端提示「重试失败项 / 移除失败照片」，用户处理完毕方可继续（不生成缺照片的相册） |
| 全相册 0 张有时间 | 聚类退化为"按上传顺序单组"；故事 date_label=null，提示用户补充至少一个日期 |
