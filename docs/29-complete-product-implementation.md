# Trailogue 完整功能迁移与交付基线

**更新日期**：2026-10-28  
**目标**：停止以独立 Wave 作为人工验收单位，以一个可在 iPhone 完整试用的真实产品闭环为交付单位。

## 1. 代码事实与产品边界

- `miniprogram/` 与 `cloudfunctions/` 是旧产品的业务规则和交互参考，不再作为运行时兼容目标。
- 主客户端为 Expo React Native iOS；主后端为 Railway Fastify API；数据为 Neon PostgreSQL；照片为私有 Cloudflare R2。
- Apple 登录、Bearer Session、Trip 创建/列表/详情、日期展示、R2 预签名上传 MVP 已有实现。
- 不使用静态页面或 Mock 数据宣称功能完成；完成状态必须有真实 API、持久化、权限校验和自动化测试证据。

## 3. 实现顺序（内部检查点，不作为人工发布阶段）

1. **核心数据与管理 API**：补齐 Trip 编辑/删除、创作设置、Photo 删除/排序/元数据、封面及关联清理。
2. **高容量照片体验**：将选择上限提升到 20+，旅行总量限制 50，加入有界并发队列、总体状态、批量重试与性能测试。
3. **故事与任务闭环**：照片事实、OpenAI-compatible Provider、故事生成 Job、状态轮询、预览、编辑、锁定、单章重生成和版本恢复。
4. **书籍、分享、导出与设置**：Book 持久化/预览、私密分享、PDF、系统分享、账号数据管理和级联删除。
5. **集中联调与发布**：一次性应用新增迁移、部署 Railway/Worker、验证 R2/Neon/AI，最后执行一份 EAS Preview Build。

## 4. 安全与数据约束

- 所有用户数据接口都必须经过 Bearer Session；跨用户资源统一返回 404。
- R2 始终私有，客户端只能使用对象级短时 URL；任何 storage key 均由服务端生成。
- 新迁移优先使用可回滚的增量 DDL；不删除现有 Staging 数据，不修改已手工执行迁移的 journal。
- AI 密钥仅存在 Railway/Worker 环境变量；照片、GPS、完整提示词和身份凭据不得进入日志。
- Trip/账号删除属于破坏性操作，只在用户明确二次确认后执行，并返回删除摘要。

## 5. 外部配置集中项

现有 Railway、Neon、R2、GitHub、Apple Developer 和 EAS 配置继续沿用。AI Provider 已确定为 DeepSeek，以下变量仅由 Railway API 服务读取：

- `DEEPSEEK_API_KEY`
- `DEEPSEEK_BASE_URL`
- `DEEPSEEK_MODEL`

运行时先读取模型列表的 `input_modalities`。配置模型不支持图片而账号可用
`deepseek-flash` 时，照片理解使用 `deepseek-flash`、故事文本仍使用配置模型；若没有任何已确认的
视觉模型，界面明确显示仅使用元数据，不把该结果描述为照片理解。
